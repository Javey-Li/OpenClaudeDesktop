- Codex never receives the extra field.

3) BRIDGE PLAN MODE. In applyPermissions:
- Read params.codeDesktop?.permissionMode / afterPlan into thread.permission.mode / afterPlan.
- Get `const planMode = ctx.get('planMode')` (API: set(agent, active) in dsh-plan-mode/lib/types/index.d.ts:140).
- When mode==='plan', call planMode?.set(thread.agent, true).
- When the previous mode was 'plan' and the new one is not, call set(false).
- Wrap both in try/catch with a logger warning.
- In the approval/request listener, when thread.permission.mode==='plan', return 'rejected' without asking. This refuses sandbox escalations in Plan; no new preset is needed.

4) QUESTIONS (pure src/questions.js). Read analysis/codex-protocol/v2/ToolRequestUserInput*.ts for the exact fields.
- `codexQuestions(items)`: each AskUserQuestionItem becomes {id, header: header ?? '', question, isOther:true, isSecret:false, options: options?.map(o => ({label:o.label, description:o.description ?? ''})) ?? null}.
  - When detail is set and intent?.kind !== 'plan-review', the question is `${question}\n\n${detail}`.
  - For plan-review, omit detail: the plan renders as a plan item.
- `harnessAnswer(items, response)`: for each question, values = response?.answers?.[id]?.answers ?? []. selected = values that equal an option label. custom = the non-option values joined with '\n' (omit custom when empty). Returns {answers:[{id, selected, custom?}]}.
- `isPlanApproval(items, answer)`: true when an item with intent.kind==='plan-review' has selected exactly [intent.approve] and no custom text.

5) BRIDGE ANSWERER (index.js).
- Register `ctx.on('user-questions/request', (request, next) => { const thread = byAgent(request.agent); return thread ? askQuestions(thread, request) : next() })`.
- askQuestions:
  - itemId = request.questions[0]?.intent?.callId ?? request.wait?.callId ?? the id of the newest inProgress dynamicToolCall in projector.activeTurn whose tool is 'ask_user_question' or 'exit_plan_mode';
  - turnId = the active turn id;
  - send transport.request('item/tool/requestUserInput', {threadId, turnId, itemId, questions: codexQuestions(...)}) with any other required params from the TS type;
  - register in thread.pendingApprovals with the same abort and serverRequest/resolved handling as askClient (index.js:315-351), and abort on request.signal.
- On response: answer = harnessAnswer(...). If isPlanApproval: thread.permission.mode = afterPlan === 'bypass' ? 'auto' : afterPlan, then re-apply presets with approvalPolicy afterPlan==='ask' ? 'untrusted' : 'on-request' and sandbox 'workspace-write', so the approved plan can be implemented in the same turn. Harness exits plan mode itself. Return the answer.
- On transport error or abort: throw the package's UserQuestionError with code 'ASK_CANCELLED'. Check the export and constructor in @deepseek-ai/dsh-user-questions lib/types; if it is not exported, throw an Error with .code='ASK_CANCELLED'.

6) PROJECTION. On tool/call 'exit_plan_mode' with a string args.plan, first push a completed item {type:'plan', id:`plan-${callId}`, text: args.plan} (check the ThreadItem 'plan' shape in analysis/codex-protocol/v2/ThreadItem.ts), then the tool item.

7) APP.
- In source-permission-menu.jsx, change the Plan description to 'Create a plan before making changes' (source shared-14:10296).
- In main.jsx, find where an item/tool/requestUserInput answer is submitted (respond-approval path). When the request has a question id 'plan-review' and the answer is ['Approve'], set the session permission to afterPlan (bypass becomes auto) through the existing permission setter, so the next turn is not re-sent as plan.

8) README: document the Plan mapping (planMode.set, escalations refused, plan review via the question card). The dedicated Rse plan card is not ported.
