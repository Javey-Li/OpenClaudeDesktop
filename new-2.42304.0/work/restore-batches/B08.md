# B08 — B8 account and usage

## Goal
Make the account and usage surfaces honest and accurate on DeepSeek:
- account/read reports whether a DeepSeek API key is actually configured;
- the no-key state is detected, with DeepSeek copy (not ChatGPT);
- token stats exclude prefix-cache hits;
- account/usage/read returns the Codex shape folded from Harness session logs;
- the stats card loads without waiting for the core.

- Evidence: Local: app/src/main.jsx:745-749 does `const b = await call("init"); setBoot(b); loadStats();`, so loadStats starts only after init resolves. app/electron/main.cjs:426-429 has the 'init' handler await `connect()`, which waits for initialize (codex.cjs:118-125, 30000 ms) and then account/read + model/list (main.cjs:210-212, request default 120000 ms in codex.cjs:175). Yet the 'stats' IPC (main.cjs:632-636) only reads config.activity. harness/README.md:73 documents the 2-4 s boot. work/deepseek-live-20261001/first-mupaykl9/01-home.png shows the skeleton card together with "Connecting to DeepSeek…". Original: the stats come from the heavy-work worker scan, independent of any agent connection, and Rw (code-home.js:13755-13761) only shows qw while that query is pending.
- Fix: In app/src/main.jsx, start loadStats() in the mount effect in parallel with init(), next to the existing `call("home-shape")` at ~line 831, and stop chaining it after `await call("init")`. The 'stats' push event (main.cjs:195) still refreshes it after turns. If the Harness stats source from home-usage-full-history-stats is added, show the ledger snapshot immediately and swap in the Harness payload once connected.
