# B09 — B9 session list, cold reads, recency, write locks

## Goal
Make the session list fast and accurate on DeepSeek:
- thread/list rows use Harness's cached titles and last prompt time;
- the sidebar loads without replaying each full log;
- opening a session does not count as activity;
- auto-archive works;
- visited sessions release the Harness write lock.

## Instructions
1) New pure src/list.js:
- `titleOf(result)` returns result?.status==='fulfilled' ? result.value?.title?.title : undefined (dsh-session-query types.d.ts:142-156; SessionTitleSnapshot.title).
- `coldRow(header, {meta, cacheValues, title})` returns {name, preview, updatedAtMs, blank}:
  - name: meta.name ?? cacheValues?.title?.title or cacheValues?.title (check the projection value shape) ?? title ?? null;
  - updatedAtMs: max(header.createdAt, cacheValues?.sessionListMetadata?.lastPromptAt ?? meta.lastPromptAt ?? 0);
  - blank: cacheValues?.sessionListMetadata?.blank === true && !meta.name.
- `matchesSearch(row, term)`: case-insensitive substring over name, preview and cwd.

2) index.js:
- In apply(), register the upstream 'sessionListMetadata' projection on ctx.sessionProjections (copy init, apply and schema from vendor/deepseek-harness/packages/api/session-controller/src/list.ts:40-80, stateVersion 1). Use ctx.get('sessionProjections'), wrap it in try/catch, and skip it if already registered.
- listThreads cold rows:
  - values from ctx.get('sessionProjectionCache')?.cachedSnapshot(header, ['title','sessionListMetadata']) (check the ProjectionSnapshot shape);
  - drop blank rows;
  - apply params.searchTerm;
  - fall back to readTitleSnapshots (titleOf) only for page rows still missing a name.
- thread/read with includeTurns !== true for a non-live id: build the Thread from (await ctx.sessionPersistence.stat(id)).header plus coldRow, with no readSession. Fall back to historyFor only when there is neither a cache entry nor a store name. A missing stat → threadNotFound (errors.js from batch 3).
- At turn/start, record store.update(id, {lastPromptAt: Date.now()}).

3) RECENCY.
- projection.js gains `lastActivityMs`, advanced only on turn/start, user/message with source.kind 'user', assistant/message and turn/end. updatedAtMs stays for internal use.
- index.js:
  - LiveThread.lastActivityMs starts null and is set from projector.lastActivityMs after hydrate;
  - onEvent copies projector.lastActivityMs after each apply, instead of Date.now() for every event;
  - threadObject uses live?.lastActivityMs ?? projector?.lastActivityMs ?? cold updatedAtMs ?? createdMs.
- desktop-settings.cjs:21: treat status 'notLoaded' like 'idle' for the inactivity sweep. Keep the existing background, child and worktree checks.

4) WRITE LOCK.
- Bridge:
  - thread/unsubscribe and thread/close answer {} immediately and close in the background;
  - skip closing when agent.status==='running', pendingApprovals.size, agent.inbox.nextTurn.length, or thread.compaction is set.
- errors.js:
  - add `sessionBusyElsewhere()`, returning RpcError(-32000, 'This session is open in another DeepSeek app. Close it there, then try again.', {codexErrorInfo:'sessionBusyElsewhere'});
  - add `isSessionOwnedElsewhere(error)`: name 'SessionAlreadyOwnedError' anywhere in the cause chain (dsh-session-persistence-jsonl errors.d.ts:21-26).
- openThread maps that error to sessionBusyElsewhere.
- App:
  - add 'thread/unsubscribe' to the main.cjs allowlist;
  - new pure session-unload-model.mjs `shouldUnload({previous, next, engine, active, pendingApproval, queued, resumed})`: true only when engine is deepseek, previous is set, previous !== next, the session is idle (no active turn), it has no pending approval or queued messages, and resumed.has(previous);
  - in main.jsx navigate/openSession, when shouldUnload, call rpc('thread/unsubscribe', {threadId: previous}) (ignore errors) and resumed.current.delete(previous). turn/start reopens through openThread.

5) README: list semantics (shared projection cache, lastPromptAt) and unsubscribe behaviour.

## Findings (audit evidence)

### sidebar-sessions-thread-list-rows-incomplete — Bridge thread/list rows: names always null, empty preview, updatedAt = createdAt, forks treated as sub-agents, searchTerm ignored [deepseek/medium/M/harness]
- User-visible: Every session that is not loaded and has no bridge-stored name lists as name null and preview "", so it would render as "New session" and sort by creation time. This affects any consumer of thread/list and blocks the resume picker. The projection cache already holds the official titles ("Remove device restrictions in WaygroundEscaper", "Fix request", "取消WGE Admin Panel登录IP限制") and lastPromptAt. User forks made in the official app would be hidden from the session list and dropped by refreshSession.
- Evidence: BRIDGE: harness/packages/codex-app-server/src/index.js:761-762 maps readTitleSnapshots entries with `entry.title ?? entry.snapshot?.title ?? entry.observation?.title`. The real shape is {sessionId,status,value:{session,title?:SessionTitleSnapshot}} (dsh-session-query/lib/types/types.d.ts:142-156), and the text is SessionTitleSnapshot.title (dsh-session-title/lib/types/types.d.ts:34-48), so every value is undefined. index.js:765-768: cold rows have no projector, so preview '' and updatedAt fall back to header.createdAt (487-488); sorting at 771-772 is therefore by creation. readTitleSnapshots also folds whole logs (one official session is at seq 84491). index.js:753 `isSub = origin==='subagent' || parentSession !== undefined` and 493-494 put parentSession into parentThreadId. SessionHeader.parentSession is fork lineage (dsh-session/lib/types/types.d.ts:70-81), so user forks are excluded from top-level lists and app/src/state.js:250-254 isSubAgentThread treats them as children (main.jsx:617-621). params.searchTerm (analysis/codex-protocol/v2/ThreadListParams.ts) is ignored. Blank sessions (projcache title null, d07d1af9…) are listed. UPSTREAM official list: vendor/deepseek-harness/packages/api/session-controller/src/list.ts:146-156 summarizeCold reads ctx.sessionProjectionCache.cachedSnapshot(header) with zero I/O (283), uses updatedAt = max(createdAt, lastPromptAt) (327-329), and folds lastPromptAt and blank via applySessionListMetadata (45-56), registered under key 'sessionListMetadata' at 80. The cache is mounted in dsh-base (cordis.patch.yml:182).
- Fix: Create harness/packages/codex-app-server/src/list.js with pure helpers. titleOf(result) returns result.status==='fulfilled' ? result.value.title?.title : undefined. coldRow(header,{meta,cache}) takes name from meta.name, then cache.values.title, then readTitleSnapshots as a fallback; sets updatedAt = max(createdAt, cache.values.sessionListMetadata?.lastPromptAt ?? meta.lastPromptAt ?? 0); sets forkedFromId = origin!=='subagent' ? parentSession : null and parentThreadId = origin==='subagent' ? parentSession : null; and filters out blank rows. In index.js apply(): inject sessionProjections and register 'sessionListMetadata' with the same zod schema, apply function and stateVersion 1 as upstream, so rows are shared with the official app's cache. Read ctx.get('sessionProjectionCache')?.cachedSnapshot(header) for cold rows. Record meta.lastPromptAt at turn/start (index.js:683-690) for older Code Desktop sessions. Classify sub-agents by origin only (753). Implement searchTerm as a case-insensitive substring match over name, preview and cwd.
- Files: harness/packages/codex-app-server/src/list.js, harness/packages/codex-app-server/src/index.js, harness/packages/codex-app-server/src/store.js
- Verification: cd harness && node --test tests/thread-list.test.mjs: titleOf on {status:'fulfilled',value:{title:{title:'Fix request'}}} returns 'Fix request'; coldRow uses cache lastPromptAt over createdAt; a header with parentSession and no origin yields forkedFromId with parentThreadId null; blank rows and searchTerm misses are excluded.

### sidebar-sessions-boot-full-replay — Each boot replays every owned session's complete log just to draw sidebar rows [deepseek/medium/M/both]
- User-visible: The sidebar skeleton stays up for longer as history grows: each owned session costs a full read and replay of its log. Official-app sessions reach tens of thousands of events (one is at seq 84491), so adopting them through the resume picker would make startup visibly slow.
- Evidence: LOCAL: app/src/main.jsx:793-799 sends one rpc('thread/read',{includeTurns:false}) per config.threadIds entry. BRIDGE: index.js:618-621 thread/read → historyFor (452-470) → sessionQuery.readSession, which reads and replay-validates the complete raw log (dsh-session-query/lib/types/index.d.ts readSession doc), then a new ThreadProjector applies every event (468-469) even though turns are discarded. ~/.dsh/storages/session_projcache/sessions/session-9c922c3d…json reports title seq 84491. - Fix: Bridge: in thread/read with includeTurns !== true for a session that is not live, build the Thread from sessionPersistence.stat(id).header plus sessionProjectionCache.cachedSnapshot(header) (title, lastPromptAt) and the bridge store, using the coldRow helper from sidebar-sessions-thread-list-rows-incomplete. ### sidebar-sessions-recency-and-auto-archive — Opening a session resets its 'last activity'; inactivity auto-archive never fires with the DeepSeek core [deepseek/medium/M/both]
- User-visible: Opening an old session without sending anything makes the core report it as updated now: archived rows from threadMetadata move to Today, and after a restart a permission-preset change can move it too. Settings → "Archive inactive sessions after N days" silently does nothing.
- Evidence: BRIDGE: harness/packages/codex-app-server/src/index.js:82 sets LiveThread.lastActivityMs = Date.now() at construction and hydrate (86-92) never resets it; index.js:99 bumps it on every live event; threadObject uses it at 488. index.js:428 applyPermissions on thread/resume can append 'permission/preset' (dsh-permission-presets/lib/types/index.d.ts:180-186), and projection.js:327-328 advances updatedAtMs on every event type, including session/title (415-420), so the persisted log also moves. index.js:489 reports every session not opened in this process as {type:'notLoaded'}. LOCAL: main.cjs:522-524 writes the resume response (updatedAt=now) into config.threadMetadata, which feeds archived rows (main.jsx:804-807). desktop-settings.cjs:21 sweep skips unless status.type==='idle' and the age exceeds N days, so unloaded sessions are always skipped and loaded ones look fresh. UPSTREAM: list.ts:327-329 updatedAt = max(createdAt, lastPromptAt), where lastPromptAt moves only on human user/message (45-56). ORIGINAL picker sorts on lastActivityAt (cc43287c9:24928).
- Fix: projection.js: add lastActivityMs that advances only on user/message with source.kind==='user', turn/start, assistant/message and turn/end; leave updatedAtMs for internal use. index.js: start LiveThread.lastActivityMs as null and set it from projector.lastActivityMs after hydrate; in onEvent bump only for those event types; threadObject uses live?.lastActivityMs ?? projector?.lastActivityMs ?? cached lastPromptAt ?? createdMs. desktop-settings.cjs:21: also treat 'notLoaded' as quiescent (`!['idle','notLoaded'].includes(thread.status?.type)`). A thread this core has not loaded has no agent or terminals here, and the existing background/child/worktree checks still apply.
- Files: harness/packages/codex-app-server/src/projection.js, harness/packages/codex-app-server/src/index.js, app/electron/desktop-settings.cjs
- Verification: cd harness && node --test tests/projection.test.mjs: a new case applies user/message at t1, then permission/preset and session/title at t2, and expects lastActivityMs === t1. cd app && node --test tests/settings-complete-model.test.mjs: a new case where thread/read returns {status:{type:'notLoaded'},updatedAt:1} expects exactly one thread/archive call.

### sidebar-sessions-write-lock-held — Every visited session keeps its Harness write lock until Code Desktop quits; a session busy in another DeepSeek app fails with a raw error [deepseek/medium/M/both]
- User-visible: After the user merely views a session in Code Desktop, the official DeepSeek app cannot continue that session until Code Desktop exits (SessionAlreadyOwnedError). Opening a session that is still open in the official app shows a raw core error in the transcript instead of the source's "Can't confirm it's closed" status.
- Evidence: BRIDGE: index.js:379-415 openThread resumes with ctx.agents.resume (390), and the LiveThread stays in `threads` until thread/delete (662-671) or thread/close/unsubscribe (673-682). The jsonl backend holds a kernel flock on session.lock for the life of the write handle; contention maps to SessionAlreadyOwnedError (dsh-session-persistence-jsonl/lib/types/lease.d.ts:1-13; errors.d.ts:21-26). The error reaches the client unmapped. LOCAL: no thread/unsubscribe or thread/close anywhere in app/src or app/electron; the main.cjs:89-121 allowlist omits them. main.jsx:1088-1096 shows the raw message as loadError. ORIGINAL: the picker marks sessions whose liveness is unknown as "Can't confirm it's closed" and skips running ones (cc43287c9:24608, 25124-25135, be(e)).
- Fix: App: add "thread/unsubscribe" to the main.cjs allowlist. In main.jsx openSession/navigate, when leaving a session that is idle (no state.active, no pending approval or queue), send thread/unsubscribe for it and remove it from resumed.current. turn/start already re-opens through openThread (index.js:684), so later sends still work. Put the policy in a pure app/src/session-unload-model.mjs. Bridge: in openThread, catch SessionAlreadyOwnedError (by error.name) and throw RpcError(-32000, 'This session is open in another DeepSeek app. Close it there, then try again.', {codexErrorInfo:'sessionBusyElsewhere'}). Optionally add an idle reaper that closes LiveThreads idle for more than 10 minutes with no pendingApprovals and agent.status !== 'running'.
- Files: app/electron/main.cjs, app/src/main.jsx, app/src/session-unload-model.mjs, harness/packages/codex-app-server/src/index.js
- Verification: cd app && node --test tests/session-unload-model.test.mjs: unload is chosen only for idle, non-current sessions without approvals or queued turns. cd harness && node --test tests/open-errors.test.mjs: a helper mapping an error named SessionAlreadyOwnedError returns an RpcError with code -32000 and data.codexErrorInfo 'sessionBusyElsewhere'.
