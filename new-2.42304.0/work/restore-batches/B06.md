## Instructions
First read the exact protocol shapes in analysis/codex-protocol/v2: ThreadItem collabAgentToolCall, CollabAgentTool, CollabAgentToolCallStatus, CollabAgentState/AgentStatus, the subAgentActivity item if it exists, and SessionSource/SubAgentSource (thread_spawn keys). Only emit enum values that exist there. Also read harness/node_modules/@deepseek-ai/dsh-subagent/lib/types (index.d.ts SubagentRunInfo/SubagentRunEndInfo, continuation-messages.d.ts) and lib/index.js ~560-660 for the exact settled-notice text.

1) projection.js:
- toolItem receives threadId (pass this.threadId from the projector).
- 'subagent' and 'subagent_fork' map to {type:'collabAgentToolCall', id:callId, tool:'spawnAgent', status:'inProgress', senderThreadId:threadId, receiverThreadIds:[], prompt: args?.prompt ?? null, model: args?.model ?? null, reasoningEffort: args?.reasoning_effort ?? null, agentsStates:{}}. Keep args.description as `description` if the type allows extra fields.
- send_message, interrupt_agent and list_agents map to collab tools ONLY when a matching enum value exists; otherwise they stay dynamicToolCall.
- completeToolItem for collab:
  - aborted → interrupted (as in batch 1);
  - text matching /^started subagent (\S+)/ → receiverThreadIds [id], agentsStates {[id]:{status:'running', message:null}}, item status 'completed';
  - foreground (one-shot) output: status completed or failed; when the projector knows the child for that call (option `childFor(callId)`, see step 3), set agentsStates[child] = {status:'completed', message: text}.
- Keep a map childId → {turn, itemId}.
- user/message with source.kind 'subagent-settled' (senderSessionId, summary):
  - map status from the summary: /interrupt|cancel/i → 'interrupted', /fail|error/i → 'errored', else 'completed';
  - message = the child's closing text from the content, with the notice preamble stripped;
  - update the owning item's agentsStates and emit item/completed for it, using its own turnId;
  - if a subAgentActivity ThreadItem exists in the protocol, also push {type:'subAgentActivity', id:`subagent-${data.id}`, kind, agentThreadId} into the current turn (ensureTurn);
  - never create a userMessage. Non-user sources are already dropped.
- Fork children: on the seeded-history end marker (check the event name and data in dsh-session lib/types types.d.ts ~400-430, e.g. 'session/end-seed' {inherited:true}), reset turns, byDshTurn, current, tools and preview so the inherited parent history is not shown as the child's own.

2) index.js threadObject / listThreads:
- parentThreadId = header.origin==='subagent' ? header.parentSession ?? null : null.
- forkedFromId = header.origin!=='subagent' && header.parentSession ? header.parentSession : null.
- Sub-agent source = {subAgent:{thread_spawn:{parent_thread_id: header.parentSession, depth: header.delegationDepth ?? 1, agent_path:null, agent_nickname: meta.agentLabel ?? null, agent_role:null}}}, adjusted to the TS keys. agentNickname = meta.agentLabel ?? null.
- listThreads:
  - wantSubAgents = params.sourceKinds?.some(k => String(k).startsWith('subAgent'));
  - isSub = header.origin==='subagent' only;
  - move readTitleSnapshots AFTER sorting and slicing, so only the returned page is folded. main.jsx:396 polls this every 2 s.

3) Live lifecycle:
- `ctx.on('subagent/start', …)` and `ctx.on('subagent/end', …)` (check the listener signature in lifecycle.d.ts). On start, for a parent that resolves (via the parent agent) to a root LiveThread:
  - store.update(childId, {agentLabel: description/label if present});
  - remember callId → childId on the parent projector when the info carries a callId (exposed through childFor);
  - notify thread/started with the child thread object (header from ctx.sessionPersistence.stat(childId)) and thread/status/changed active.
- On end, notify thread/status/changed idle for the child.
- Child transcripts are NOT streamed live in this batch; the UI opens them with thread/read.

4) turn/interrupt for an id that is not in `threads`:
- use ctx.agents.get?.(id)?.cancel({kind:'user'}) (check the AgentRegistry API in dsh-agent types);
- else ctx.get('subagents')?.interrupt?.(id), if such a method exists.

5) Manual-mode gating for children:
- In approval.js (from batch 5), move READ_ONLY_TOOLS from index.js:43 and add:
  - `rootThreadFor(agent, threads)`: walk agent.session.header.parentSession through the threads Map, max depth 8;
  - `childDecision({rootPolicy, toolName})`: 'ask-client' when rootPolicy==='untrusted' && !READ_ONLY_TOOLS.has(toolName), else 'next'.
- In the pre-execute hook, when byAgent(exec.agent) is undefined and childDecision says ask-client:
  - return next().then(async d => d?.kind==='deny' ? d : (await askClient(root, {callId: exec.callId, toolName: exec.name, signal: exec.signal, childArgs: exec.args, itemId: <root's inProgress collab item for that child, else newest inProgress spawnAgent>})) === 'allowed-once' ? {kind:'allow'} : {kind:'deny', reason:`the user rejected tool "${exec.name}"`});
  - check the pre-execute decision shapes in dsh-tools types.
- askClient builds the command from childArgs when no item is found (bash → args.command), treats the origin as 'ask', and uses the given itemId.
- Children are pinned to approval 'never', so returning 'ask' would be auto-denied. That is why the hook asks directly.

6) README: subagent mapping; limitation: no live child stream; child approvals appear on the parent card.

- User-visible: In Manual mode the user approves one card reading "subagent {…json…}". The child agent then creates and edits files and runs commands in the workspace with no further approvals. Under Codex, sub-agent approvals appeared in the owning session.

- Fix: In the pre-execute listener, resolve the owning root LiveThread by walking exec.agent.session.header.parentSession through `threads`. If that root is 'untrusted' and the tool is not in READ_ONLY_TOOLS, ask the client directly from the listener rather than returning 'ask', because ctx.approval would reject it under the child's pinned 'never'.
