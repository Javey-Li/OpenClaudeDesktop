## Instructions
1) BRIDGE CAPABILITIES. In index.js, define `const CAPABILITIES = { unsupportedMethods: ['thread/fork','review/start','thread/revert'] }` and add `capabilities: CAPABILITIES` to the initialize result. Later batches add keys to this object.

2) BRIDGE NOT-FOUND. New src/errors.js:
- `threadNotFound(id)` returns new RpcError(INVALID_PARAMS, 'This session is not available in DeepSeek Harness.', {codexErrorInfo:'threadNotFound', threadId:id}).
- `isSessionNotFound(error)` checks error?.code === 'SESSION_QUERY_SESSION_NOT_FOUND' (dsh-session-query/lib/index.js:311,524,904), or the same anywhere in error.cause.
- historyFor: wrap query.readSession in try/catch and rethrow threadNotFound(id) when isSessionNotFound. A missing snapshot.session also throws threadNotFound.
- openThread: a missing stat or header throws threadNotFound.
- RpcError is not stack-logged by transport.js:88, so the per-id stderr stacks disappear.

3) APP PLUMBING.
- In main.cjs connect() (~line 214), add to `initial`: `core: { engine: owner.serverInfo?.engine ?? 'codex', engineVersion: owner.serverInfo?.engineVersion ?? null, capabilities: owner.serverInfo?.capabilities ?? {}, configPath: owner.serverInfo?.configPath ?? null }`.
- The 'init' handler already spreads status, so the renderer gets boot.core. Keep boot.core when the 'connection' event updates boot.

4) New app/src/session-engine-model.mjs (pure):
- `sessionEngine(meta)` returns:
  - 'deepseek' if String(meta?.cliVersion) starts with 'dsh ';
  - 'codex' if /^\d/.test(cliVersion) or meta?.modelProvider === 'openai';
  - else null.
- `coreEngine(core)` returns core?.engine === 'deepseek-harness' ? 'deepseek' : 'codex'.
- `partitionSessions({ids, results, metadata, archivedIds, engine})` returns {active, archived, otherEngine, missing}:
  - active: fulfilled threads sorted by updatedAt desc;
  - archived: metadata rows for archivedIds whose sessionEngine equals engine, or is null when engine === 'codex', marked archived:true;
  - otherEngine: count of rejected ids plus excluded archived ids whose metadata engine is known and differs from the current engine;
  - missing: all other rejected ids.
- Never mutate config ids, so switching back to Codex restores everything.

5) main.jsx loadSessions (793-812): use partitionSessions with engine coreEngine(b.core). Keep {otherEngine, missing} in state and pass it to SourceSidebar.

6) source-sidebar.jsx:
- When otherEngine > 0, render one muted notice line at the top of the session list, styled with existing footnote/empty-state classes: `${n} Codex session${n===1?'':'s'} aren’t available with the DeepSeek core. Start Code Desktop with CODE_DESKTOP_CORE=codex to open them.`
- When missing > 0, add `${n} session${s} could not be loaded.`

7) DELETE COPY.
- Change deleteConfirmCopy(sessions, {engine}={}) and olderConfirmCopy(action, count, {engine}={}). For engine 'deepseek':
  - single: title 'Remove session?', body `“${name}” will be removed from Code Desktop. Its history stays in DeepSeek Harness (~/.dsh/sessions) and other DeepSeek apps.`, confirmLabel 'Remove';
  - plural: 'Remove N sessions?' with `These N sessions will be removed from Code Desktop. Their history stays in DeepSeek Harness (~/.dsh/sessions) and other DeepSeek apps.`;
  - older delete: title 'Remove older sessions?', body `This will remove ${plural(count,'session')} older than a week from Code Desktop. Pinned sessions aren’t affected. Their history stays in DeepSeek Harness.`, label 'Remove all';
  - keep danger:true.
- Codex keeps the source strings exactly.
- Thread the engine from boot.core down to every call site; grep both function names.

8) UNSUPPORTED COMMANDS.
- In session-command-model.mjs add `const COMMAND_METHODS = {fork:'thread/fork', review:'review/start', rewind:'thread/revert'}`.
- In commandUnavailable, check FIRST: `if (context.unsupportedMethods?.includes(COMMAND_METHODS[command.id])) return 'Not available with the DeepSeek core yet'`.
- main.jsx builds commandContext.unsupportedMethods from boot.core?.capabilities?.unsupportedMethods.
- Make sure the session menu, titlebar menu and rewind entry points (main.jsx ~1349-1358, 1409-1427, 1892-1896) use commandUnavailable for their disabled state and tooltip. Where they do not, add it.

9) README: document capabilities, boot.core and threadNotFound.

## Findings (audit evidence)

### sidebar-sessions-codex-sessions-vanish — Existing Codex sessions silently disappear under the DeepSeek core; the archived Codex row is shown but cannot be opened [deepseek/high/M/both]
- User-visible: After the core switch, the user's real profile (~/Library/Application Support/Code Desktop/preferences.json) has 10 active thread ids, all Codex rollouts (cliVersion 0.155.1, modelProvider openai), and 1 archived id. The sidebar now shows none of the 10 and gives no explanation. Pins and groups for them are orphaned. The archived Codex session still appears under the Archived filter, but opening or unarchiving it fails or makes it vanish on the next launch.
- Evidence: LOCAL: app/src/main.jsx:795-803: rejected thread/read results are filtered out without a notice. main.jsx:804-807: archived rows come straight from stale config.threadMetadata. main.jsx:1074: archived rows open via thread/read, and the catch at 1088-1096 shows the raw error. main.cjs:543-546: unarchive moves the id into threadIds whether or not the core knows it. BRIDGE: index.js:452-467 historyFor → sessionQuery.readSession throws for ids that are not in ~/.dsh. index.js:659-660: thread/unarchive swallows that failure and returns {}. The connection already reports its engine (index.js:577 `engine: 'deepseek-harness'`, stored as client.serverInfo at codex.cjs:126), but nothing in the app reads it. ORIGINAL: the sidebar contract lists only sessions the host can open; there is no dead-row state (sidebar-groups.js 7600-7705 empty/filter variants assume every listed row is openable).
- Fix: Bridge: in historyFor/openThread, map a missing session to RpcError(INVALID_PARAMS, 'Unknown session', {codexErrorInfo:'threadNotFound'}). App: (1) main.cjs connect() adds `engine: owner.serverInfo?.engine ?? 'codex'` to `initial`. (2) New app/src/session-engine-model.mjs: sessionEngine(meta) returns 'deepseek' when cliVersion starts with 'dsh ', otherwise 'codex' when cliVersion is numeric or modelProvider is 'openai'; partitionSessions({ids, metadata, results, engine}) returns {available, otherEngine, missing}. (3) loadSessions keeps otherEngine ids out of the list but shows one sidebar notice: "N sessions were created with Codex. Set CODE_DESKTOP_CORE=codex to open them." It also filters archived rows by engine, so dead rows are never shown. Do not delete the ids, so switching back to Codex restores them.
- Files: harness/packages/codex-app-server/src/index.js, app/electron/main.cjs, app/src/session-engine-model.mjs, app/src/main.jsx, app/src/source-sidebar.jsx
- Verification: cd app && node --test tests/session-engine-model.test.mjs: a fixture metadata map with cliVersion '0.155.1'/openai and 'dsh 0.2.0-rc.2'/deepseek-official.
