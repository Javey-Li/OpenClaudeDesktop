## Instructions
Decision: follow the renderer find provider ZB (sidebar-main.js:17787-18130), which the Code surface uses when the transcript registers as a provider (scroll-messages-current.js:62900-63071). Do not use webContents.findInPage. B4 already made the Edit menu explicit; re-read app-menu.cjs.

1) Find model: new pure transcript-find-model.mjs.
- Collect text ranges from the .source-transcript-content tree, skipping [data-find-omitted], aria-hidden and .sr-only nodes.
- Case-insensitive matching, wrap-around active-index navigation, and an empty query gives 0/0.
- Re-run on content mutation (MutationObserver, debounced) and keep the active index stable.
- Ignore input while IME composition is in progress.

2) Find bar UI: new source-find-bar.jsx/.css, portaled to body.
- Placement and surface: fixed at top 56px (top-14), right 16px. rounded-lg, 0.5px border-strong, surface-3, shadow-lg.
- Input: placeholder 'Find…', aria-label 'Find'.
- Status: '{current}/{total}', or '0/0'.
- Three 24px buttons (QB: size-6, rounded, text-muted, hover surface-0, disabled opacity .4): 'Go to previous match', 'Go to next match', 'Close find bar'.
- Paint all matches with ::highlight(transcript-find) plus an active-match highlight, as the existing ::highlight(source-file-line) pattern does.
- Scroll the active match to the viewport centre through the transcript controller, releasing follow.

3) Keys (main.jsx).
- ⌘F opens the bar, or selects the existing query. Enter / Shift+Enter, ⌘G / ⇧⌘G and F3 step.
- Escape closes the bar and restores the previously focused element.
- Respect defaultPrevented and B2's layering. A pane-owned find, e.g. in the Files pane, wins when focus is inside that pane.
- app-menu.cjs: append to the Edit submenu a separator and a 'Find' submenu (ISr), each item using registerAccelerator:false or a hidden-twin pattern because the renderer handles the keys:
  - 'Find…' CmdOrCtrl+F → emit find-open
  - 'Find Next' CmdOrCtrl+G → find-step forward
  - 'Find Previous' CmdOrCtrl+Shift+G → find-step back
- main.jsx onEvent handles both events.

4) Feed structure (scroll-messages-current.js:60985-61288 N9, :63471, :63957-63966, :61757-61761, :56941-56953, :39513-39521; scroll-transcript-host-current.js:2982).
- source-transcript.jsx: the viewport gets role="feed", aria-label="Chat messages", aria-busy={responding} and aria-describedby pointing to an sr-only <p data-find-omitted> reading 'Use the up and down arrow keys to move between messages.'.
- New pure transcript-feed-nav.mjs: next, prev, home and end index math, skipping hidden rows.
- New hook use-transcript-feed-nav.js:
  - Top-level message rows are user/assistant [data-transcript-item-id], plus only the first row of a tool group.
  - Each gets role=article, aria-posinset/aria-setsize, a roving tabIndex (0 on one row, -1 elsewhere), and aria-label 'Message N', or 'Currently streaming message' on the live tail.
  - ArrowUp, ArrowDown, Home, End, Ctrl+Home and Ctrl+End act only when the target is not editable.
  - Moving focus calls scrollIntoView({block:'nearest'}) and releases follow. End on the last row re-pins via api.jumpToLatest.
  - Escape inside an article focuses the composer.
- Add sr-only h2 headings: 'You said: {prompt}' in SourceUserMessage, and 'Claude responded: {summary}' at the turn head. The summary is the first plain-text line, truncated. Apply the project's Claude→DeepSeek naming rule if the transcript copy already substitutes the assistant name.
- Pass responding from main.jsx.
- Removing role=log also stops screen readers from announcing every streamed delta.

5) Scripts: grep app/scripts for role log / 'Conversation' selectors and update them to feed / 'Chat messages'. Register a new 'transcript-find' suite in run-suite.mjs only if needed; otherwise extend 'session'.
