## Instructions
1) LIVE STREAM MAPPER.
- Move the logic of LiveThread.onStream/emitStart (index.js:170-224) and its `streams` map into a new exported class `LiveStreamMapper` in projection.js.
- Interface: `constructor({threadId, projector})`, `frame(frame, nowMs)` returning an array of {method, params}, and `endTurn(dshTurn)`, which replaces index.js:113-115.
- Keep current behaviour unchanged:
  - a retried attempt re-emits item/started (reset) for the previous attempt's items;
  - ensureTurn runs when the Codex turn has no id yet;
  - non-committed `end` clears its items.
- NEW, chunk.type==='block-end' for a known stream item with chunk.block?.type 'reasoning' or 'text': emit item/completed with completedAtMs = nowMs.
  - reasoning item: {type:'reasoning', id, summary:[chunk.block.text ?? ''], content:[]}
  - text item: {type:'agentMessage', id, text: chunk.block.text ?? '', phase:null, memoryCitation:null, delivery:null, questions:null}
  - id: assistantItemId(turn, step, index)
  - Ignore tool-call blocks.
- NEW, in the abandoned-attempt branch, the cleared reasoning body also carries reasoningText:''.
- index.js: LiveThread owns `this.stream = new LiveStreamMapper(...)`. onStream returns early while hydrating, otherwise notifies every note. The later committed assistant/message still emits item/completed; the reducer merges by id, so the duplicate is harmless.

2) TOOL OUTCOMES.
- In ThreadProjector.apply, track `approval/asked` (data.id → data.callId). On `approval/decided` with outcome 'rejected', add that callId to `this.rejectedCalls`.
- In the tool/result case, pass `error: data.error` and `rejected: this.rejectedCalls.has(message.toolCallId)` into completeToolItem.
- In completeToolItem, set `aborted = error?.name === 'AbortError'` (codes ABORTED and ABORTED_BEFORE_DISPATCH). Fallback for logs without error info: content text exactly 'Error: tool call aborted' or 'Error: tool call aborted before dispatch'.
- When aborted, return status 'interrupted' with no error body:
  - commandExecution: aggregatedOutput null, exitCode null, keep durationMs;
  - fileChange: no `error` field;
  - webSearch: status only;
  - mcpToolCall: result null, error null;
  - dynamic: contentItems [], success null.
- When rejected and not aborted:
  - commandExecution and fileChange get status 'declined' (commands: aggregatedOutput null, exitCode null; fileChange: no error);
  - other types stay 'failed' with success:false.
- In the turn/end case (projection.js:447-449), settle leftover inProgress items to 'interrupted' when turn.status==='interrupted', else 'failed'.
- Update the assertion at harness/tests/projection.test.mjs:60 to expect 'interrupted'.

3) READ CARD. In completeToolItem's `view?.card === 'read'` branch:
- When Array.isArray(view.lines), set aggregatedOutput = view.lines.map(l => `${l.number}: ${l.text}`).join('\n').
- Otherwise strip the footer from textOf(view.content).
- Extend the footer regex at projection.js:205 so it also matches '(Output capped. …)' (dsh-tool-fs formatReadOutput emits that variant). Use the same regex in both branches.

4) WEB AND GLOB.
- In toolItem, move the `name === 'web_search' || name === 'web_fetch' || kind === 'fetch'` branch ABOVE the search branch.
- Restrict the search branch to `name === 'grep' || name === 'glob' || (kind === 'search' && !Array.isArray(args?.queries))`.
- Map glob to the action {type:'search', command, query: args?.pattern ?? null, path}, so the row reads 'Searched <pattern>' as in the source Glob label.
- webSearch items start with status:'inProgress'.
- In completeToolItem webSearch, status = aborted ? 'interrupted' : failed ? 'failed' : 'completed'.
- results:
  - search: view.sources when view.card==='web' && view.kind==='search';
  - openPage (web_fetch) that succeeded: the raw text;
  - otherwise null.
- On failure set error to {message: text}.

5) RESUME REPLAY.
- In the projector's assistant/message case, also set `this.lastUsageTurnId = turn.id` when data.usage exists.
- In index.js thread/resume, after building the response, call `setImmediate(...)` (so the notifications land AFTER the response line). Inside it, skip if thread.closing. Otherwise:
  - if projector.lastUsage, notify thread/tokenUsage/updated {threadId, turnId: projector.lastUsageTurnId ?? projector.turns.at(-1)?.id ?? '', tokenUsage: thread.tokenUsage(projector.lastUsage)};
  - if projector.plan?.length, notify turn/plan/updated {threadId, turnId: projector.turns.at(-1)?.id ?? '', explanation:null, plan: projector.plan}.
- The plan replay is the bridge half of handoff-backlog-plan-pane-source-list. The glob mapping is the bridge half of tool-rows-harness-tool-labels. Later batches only do the app side of those findings.

6) APP.
- transcript-runtime-stats.mjs turnActivityLabel: keep the compaction and tools precedence. Return the thinking ladder only when the LAST live item of the turn (array order) is a reasoning item. When an agentMessage after it is streaming, return null.
- generic-tool-model.mjs output() for webSearch:
  - when results is an array of objects with string url, format each entry as `${title || url}\n${url}`, plus `\n${snippet}` when present, with entries separated by blank lines;
  - when results is a string, return it unchanged;
  - keep the JSON fallback for any other shape.
- No other app change is needed: command-row-model already maps interrupted→stopped and declined→denied.
