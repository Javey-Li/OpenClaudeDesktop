## Instructions
1) New src/input.js (pure apart from file reads):
- `encodeTextPart(part)` holds the canonical text forms:
  - localImage fallback → `[Attached image: ${path} — use read_image to view it]`;
  - image URL → `[Attached image URL: ${url}]`;
  - mention → `[Referenced: ${path}]`;
  - skill: `/${name}` when isSkillName-like /^[a-z0-9]+(?:-[a-z0-9]+)*$/. That is dsh-tool-skill's SKILL_GESTURE, which injects the skill body. Otherwise `[Use the ${name} skill (${path})]`.
- `async toHarnessContent(input, {imageAllowed, attachments, modelName})`:
  - text → text block;
  - localImage: when attachments exists and imageAllowed, read the bytes, take mediaType from the magic bytes (png, jpeg, gif, webp) and call attachments.saveImages(batch) ONCE per message in order (Uint8Array data, name = basename), emitting {type:'image', attachment: ref} in place;
  - localImage when !imageAllowed and attachments exists: throw RpcError(INVALID_PARAMS, `Model "${modelName}" does not support image input.`);
  - localImage with no attachment store: the text fallback;
  - others → encodeTextPart.
- `toCodexInputs(content, {imagePath})`:
  - a text block whose ENTIRE text matches one of the bracket forms → the corresponding part ({type:'localImage', path}, {type:'image', url}, {type:'mention', name: basename(path), path}, {type:'skill', name, path});
  - '/name' gesture blocks stay text;
  - an image block → {type:'localImage', path: imagePath(ref)} when a path is returned, else a text part '[image]';
  - other text → {type:'text', text, text_elements:[]}.
- index.js:
  - inputMessage becomes async and uses toHarnessContent;
  - imageAllowed comes from the selected route's catalog entry info.inputModalities including 'image' (thread.selection.current; catalog.entries);
  - attachments = ctx.get('attachments');
  - update every caller: turn/start, turn/steer, and queue add/update in queue.js and index.js from batch 2.
- projection.js:
  - replace userInputsOf with toCodexInputs;
  - ThreadProjector accepts an `imagePath` option; index.js passes (ref) => ctx.get('attachments')?.imageHostPath(ref) at both projector constructions (LiveThread and historyFor);
  - preview and title use text parts only, with no markers;
  - keep exporting userInputsOf as an alias for compatibility.

2) App image gating:
- In composer-attachments-model.mjs stageFiles (or the staging function used by paste and drop), add an option imagesAllowed. When it is false, refuse image entries and return a notice 'The selected model doesn’t support image input.'
- main.jsx and source-composer.jsx pass imagesAllowed = chosen model's inputModalities includes 'image', or true when inputModalities is absent (Codex).

3) Catalog labels:
- models.js:115 description = entry.model.description ?? ''.
- Default model 'deepseek-flash' in packages/code-desktop-app/cordis.patch.yml and in the Config default at index.js:34.
- source-model-menu.jsx:63: drop the local 'Default' badge (show catalog badges only).
- source-composer.jsx:466: aria-label `Effort: ${capitalized effort name}`. grep app/scripts and app/tests for 'Reasoning effort' and update those selectors.
- source-settings.jsx:211: capitalized effort names.

4) Fast section:
- New pure model-menu-model.mjs `modelMenuSections({models, fastTier})` → {primary, overflow, showFast: !!fastTier}. Move the first-four split from source-model-menu.jsx:27-36 into it.
- source-model-menu.jsx renders the Fast separator, header and row only when showFast. Keep the /fast and Cmd+Alt+F gating unchanged.

5) README: images now use Harness attachments; the limitation applies only to models without image input.
